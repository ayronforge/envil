---
title: Resolver Adapters
description: Resolve authoritative server secrets with schema-bound adapters.
---

Resolvers are configured through a schema-bound callback:

```ts
import { createEnv, requiredString } from "@ayronforge/envil";
import { awsSecretsAdapter } from "@ayronforge/envil/aws";
import { gcpSecretsAdapter } from "@ayronforge/envil/gcp";

export const env = createEnv({
  server: {
    DATABASE_PASSWORD: requiredString,
    STRIPE_SECRET_KEY: requiredString,
  },
  resolvers: ({ resolve }) => [
    resolve(awsSecretsAdapter, {
      region: "us-east-1",
      secrets: {
        DATABASE_PASSWORD: "production/database#password",
      },
    }),
    resolve(gcpSecretsAdapter, {
      projectId: "my-project",
      secrets: {
        STRIPE_SECRET_KEY: "stripe-secret-key",
      },
    }),
  ],
});
```

`resolve` autocompletes only `server` keys, preserves adapter-specific options,
and carries adapter errors and Effect requirements into the final Effect.

Resolver values are authoritative. `Option.none()` means the secret does not
exist; Envil never falls back to `process.env`. Duplicate resolver keys are
rejected at typecheck and runtime.

Provider SDKs are dynamically imported by their own subpath adapter. Importing
AWS never loads Azure, GCP, or 1Password.
