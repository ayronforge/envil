---
title: Environment Composition
description: Compose already-created environment values with extends.
---

`extends` combines validated environment values while preserving their bucket
metadata and client-access protection.

```ts
// database-env.ts
import { createEnvSync, port, redacted, url } from "@ayronforge/envil";

export const databaseEnv = createEnvSync({
  server: {
    DATABASE_URL: redacted(url),
    DB_PORT: port,
  },
});
```

```ts
// env.ts
import { createEnvSync, requiredString } from "@ayronforge/envil";
import { databaseEnv } from "./database-env";

export const env = createEnvSync({
  extends: [databaseEnv],
  server: {
    APP_NAME: requiredString,
  },
});
```

Each extended environment is validated at its own creation boundary. A key may
not appear in different buckets across the composed metadata.

`InferEnv<typeof env>` includes both inherited and locally defined values. The
same composed contract is used by `envil example`.

Each creation boundary can also compose unresolved environments of its own
modality: `createEnv` resolves Effects, `createEnvPromise` awaits Promises, and
`createEnvSync` accepts resolved values only. Resolved environment values can be
composed at any boundary.
