## Buckets and exposure

- `server` contains values that must stay on the server.
- `client` contains values intentionally exposed to client bundles.
- `shared` contains unprefixed values that may execute in both environments.

A logical key may exist in only one bucket. Redacted schemas and resolver keys
are server-only.

## Logical and physical keys

Schemas and resolvers use logical keys:

```txt
APP_URL
DATABASE_PASSWORD
```

Runtime environment objects use physical keys after bucket prefixes:

```txt
VITE_APP_URL
APP_DATABASE_PASSWORD
```

```ts
prefix: {
  server: "APP_",
  client: "VITE_",
}
```

Envil rejects physical collisions after prefixes are applied. Resolver
configuration always uses logical, unprefixed server keys.

## Redaction

`redacted(schema)` decodes to `Redacted<T>`. Resolver-derived values are
redacted automatically and cannot opt out.

For optional resolver values, the result is:

```ts
Redacted<string> | undefined
```

It is never `Redacted<string | undefined>`.

## Type inference

```ts
import type { InferEnv } from "@ayronforge/envil";

type Environment = InferEnv<typeof env>;
```

`InferEnv` returns the complete decoded environment type. It works with an
Effect, Promise, synchronous value, or awaited value, includes composed
environments, and preserves `Redacted<T>` values.

Envil retains additional structural metadata internally for CLI inspection.
That metadata is phantom: no `__envilContract` property exists at runtime.
